# 数据对象功能设计

## 目标与范围

在数据资产下增加数据对象，参考 `D:\sparta-project\sparta-damp` 的目录、对象列表、建表、物理表批量注册及字段管理流程，沿用当前项目的导航、工具栏、目录树和分页规范。覆盖当前已实现的 MySQL 5.x/8.x、PostgreSQL、Oracle 11g/12c+ 数据源及其现有驱动配置。对每种数据库使用对应方言与实际驱动，不以单一数据库结果推断其他数据库可用。

## 页面

列表左侧为多级目录树；右侧查询对象表名、中文名，点击查询或回车生效，支持后端分页。右侧操作按顺序放置“新增”“注册”“导出”“刷新”。列表显示对象名称、中文名、数据源、目录、更新时间及预览、查看、编辑、复制、删除。桌面端目录和列表面板占满工作区，分页位于列表底部；窄屏时目录置于列表上方并限制高度。

目录支持新增子目录、重命名、删除；非空目录禁止删除。列表选择目录时包含后代目录，根节点显示全部对象。目录操作写入审计。

## 新增、注册与对象维护

“新增”选择数据源及目录、填写物理表名、中文名、描述和字段定义；字段至少包含名称、类型、长度、精度、可空、主键、注释。各数据库类型选项由对应方言的明确白名单生成；不支持的类型或变更不能进入执行。用户先预览建表 SQL、目标数据源及数据库/模式，再明确确认执行；成功创建后登记对象和字段快照。

“注册”选择数据源、所属目录和数据库/模式，从物理表列表中多选已有表；读取各表字段及主键、注释，允许逐表填写中文名和描述，确认后逐表登记，展示成功和失败及原因。注册只读取数据库元数据，不修改物理表。物理对象以数据源、catalog、schema、表名和对象类型的完整身份标识；相同身份不能重复登记。视图在注册列表中明确标示，仅提供只读元数据及预览，不提供结构发布。

对象资料编辑只保存中文名、描述和目录，不修改物理表。字段结构编辑先建立草稿，展示当前结构与目标结构的差异、目标数据库和生成的 SQL，再由具备结构发布权限的用户确认执行。仅允许后端按数据库方言白名单生成并执行 SQL，不接受用户提交的任意 SQL。标识符按数据库规则验证和引用，数据源范围沿用现有连接与元数据安全约束。执行前重新读取实际表结构并比较版本指纹；不一致时拒绝执行，提示刷新并重新预览。

首版支持新增字段、修改字段类型/长度/精度/可空性及删除字段；主键变更、字段重命名和视图结构修改不支持，并在界面说明。每种数据库只启用已实现并通过验证的具体操作；不支持的类型转换或语法在预览时明确拒绝。删除字段、缩短长度、变更类型或收紧可空约束属于可能丢失数据的变更，预览中逐项标注风险，确认时明确列出受影响字段；若数据库拒绝变更，展示脱敏的失败原因。

复制以原对象字段生成新建表草稿；用户必须选择目标数据源、目录及新的表名，确认预览并创建物理表后才登记为新对象，不复制表数据。删除操作只删除平台对象登记和其平台侧元数据，保留数据源中的物理表和数据；对象被平台内任务或其他实体引用时拒绝删除并展示引用，直到解除引用。

## 类型、元数据和预览

连接统一使用现有 `ConnectionFactory`、数据源凭据管理及驱动档案。复用现有元数据发现能力并扩展字段精度、主键和注释读取；不得丢失 catalog/schema 身份。对于驱动未提供的元数据明确显示“未知”，不将未知误判为非空、无主键或零精度。MySQL 受连接配置数据库范围限制；PostgreSQL 和 Oracle 按目标数据库的 schema 与用户权限约束。

类型映射、长度精度、标识符大小写及引用规则由独立的 MySQL、PostgreSQL、Oracle 方言处理，并按 MySQL 5.x/8.x、Oracle 11g/12c+ 版本限制生成受支持语法。仅允许可可靠映射的类型参与建表和结构发布；对无法可靠表达的数据库原生类型保留原始元数据用于展示与注册，禁止自动更改该字段。预览调用现有受控查询能力，强制行列权限、数据范围、行数上限和超时；若对象尚未配置必要数据权限则拒绝预览。导出仅导出对象及字段元数据，不导出业务数据，并对导出范围与条数设限。

## 一致性与恢复

物理建表或 DDL 可能自动提交，不能假设与平台数据库处于同一事务。执行记录必须先持久化操作 ID、目标身份、原结构指纹、目标定义和状态，避免并发或重复提交；同一对象同一时间只允许一个结构发布。建表前检查表是否存在，执行后重新读取并核对；物理建表成功但平台登记失败时，标记待恢复，展示表的确切身份并提供重新登记，不自动删除物理表或再次执行建表。

结构发布按预览显示的顺序执行并记录每条语句结果；任一步骤失败或连接中断时停止后续语句，重新读取实际结构并标记部分成功或结果待核实，不声称已回滚。用户须根据实际结构重新编辑和预览。平台对象的已发布快照仅在重新读取验证成功后更新；失败保留草稿和错误记录。错误信息去除连接凭据，不把密码、业务数据或完整连接串写入日志。

## 权限与审计

新增独立权限：目录查看/新增/修改/删除、对象查看、注册、新增建表、修改资料、发布结构、删除登记、预览和导出。后端逐接口校验，前端按权限展示入口；默认超级管理员获得全部新权限，其他角色仅在授权后使用。注册和建表所需的数据源读取、连接和目标数据库权限也分别校验。

目录新增、修改、删除，以及对象注册、建表、资料修改、结构发布、删除登记、预览和导出分别记录成功与失败；审计保存操作者、对象、目标数据源和操作结果，不记录业务数据或凭据。为各操作和对象类型在 `AuditCatalog` 注册中文名称，使审计列表、筛选、详情和导出均显示中文。

## 验证与交付

- 测试目录权限、层级与非空删除，查询、后端分页和完整物理身份去重。
- 测试批量注册的成功与逐项失败、重复登记、缺失元数据以及不同 schema 同名表。
- 分别验证各数据库版本的类型映射、标识符引用、建表、支持的结构变更、过期预览拒绝和失败恢复；编写 SQL 方言单元测试，并在 MySQL 5.x/8.x、PostgreSQL、Oracle 11g/12c+ 实例上进行集成验证。若某版本实例不可用，明确记录未验证范围及限制，不宣称该版本已实测。
- 验证权限隔离、受控数据预览、审计中文名称、操作结果、导出和凭据脱敏。
- 使用当前项目界面验证桌面和窄屏目录、列表、建表预览、注册与失败反馈；数据库写操作在专用测试库执行。
