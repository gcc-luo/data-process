# 主数据功能设计规格

## 目标

参考 `sparta-damp` 的主数据记录管理，在当前项目“数据资产”下增加“主数据”二级菜单。该页面面对的是**全部已登记数据对象**：对象目录只用于组织和查找，不把对象范围限制在当前选中的数据对象目录内。选择对象后，按对象字段展示并管理其物理记录。

页面沿用当前数据资产模块的 Element Plus 控件、字号、颜色、间距和表格样式；目录面板、左右工具栏、窄屏和滚动行为遵循项目 `AGENTS.md` 约定。视觉伴侣原型已获用户确认：`http://localhost:50563`。

## 已确认的权限边界

- 主数据使用单独的角色权限。获授主数据权限的用户可以跨所有数据对象管理记录。
- 主数据的授权不改变数据查询模块既有的数据集、行范围或列脱敏策略；数据查询继续按原规则运行。
- 主数据页面通过受 `datasource.master_data.read` 保护的专属接口读取全局对象目录和字段元数据，不能依赖数据对象管理模块的目录/对象权限，否则会漏掉只获授主数据权限的对象。
- 服务端每个 API 都按主数据权限校验；前端按当前会话权限隐藏无权操作。

## 页面和对象范围

1. 在“数据资产”下增加“主数据”菜单项，组件标识为 `assets/master-data`。首次数据库迁移和默认管理员初始化后，管理员能进入新菜单；角色管理中能看到并分配主数据权限。
2. 左侧对象树列出所有已登记数据对象，按已有对象目录分组；根节点代表全局范围。目录搜索同时匹配物理表名和对象中文名，且不受列表页之前选择的目录影响。
3. 选择对象后，主区展示对象名称、数据源和目录信息，以及根据对象字段元数据动态生成的记录表格和过滤条件。过滤通过“查询”按钮应用，文本条件支持回车；列表操作位于工具栏右侧。
4. 对象没有选择时展示清晰的空状态。没有已登记对象时提示先去数据对象模块登记对象。
5. 所有登记对象均可在树中找到。`TABLE` 对象可按下述条件执行记录写操作；`VIEW` 对象只读。对象缺少可确认的主键时仍可读取、导出；不得对其执行编辑或删除，以免误更新多行。平台不为对象自动补充“状态”等业务字段；对象实际包含的字段均作为普通字段显示。

## 记录管理

- 数据表按物理字段动态生成列表列、筛选项和新增/编辑表单；表单使用字段类型、长度、可空属性和注释。列表支持分页、刷新和精确到所选对象的查询。
- 支持新增、编辑、删除单条物理记录。编辑和删除使用登记字段元数据确认的单列或复合主键；服务端重新校验对象类型、字段集合及主键，标识符只允许来自可信元数据，值使用 JDBC 参数绑定。
- 新增/编辑校验必填、类型和字段长度；新增时识别自增/生成列和数据库默认值，未填写时由数据库生成或填充；数据库约束冲突以可理解的中文提示返回。删除需要二次确认。
- `VIEW` 的新增、编辑、删除入口不可用；后端也拒绝相应请求。
- 不提供对任意对象执行任意 SQL 的接口。

## 查询、导入、导出和记录历史

- 查询条件依据当前对象的字段生成，允许按字段筛选，不要求不同对象具有相同列。所有筛选值参数化；分页和查询范围有服务端上限。
- 提供当前数据表的 Excel 模板下载、Excel 导入和 Excel 导出。导入按列名匹配字段、逐行校验并返回成功/失败数量及失败行原因；视图不可导入。导出只包含当前对象和当前筛选结果，不导出数据库连接凭据或内部配置。
- “版本记录”打开所选对象的记录变更历史，列出新增、修改、删除及导入产生的操作，可查看某次修改的字段差异。为便于回溯，主数据版本数据保存在平台数据库；查看历史单独受 `history` 权限控制。历史记录和审计文本不把单元格值写入通用审计消息。
- 原主数据实现中的状态审批、标签、编码规则不作为全对象的通用属性。没有对象级元数据可证明这些属性存在时，不创建虚假的通用状态或标签操作。

## 权限、初始化与审计

- 在代码权限注册表和权限目录初始化中新增独立的 `datasource.master_data` 权限：查看记录、创建、修改、删除、导入、导出、查看版本记录。各 API 路径固定映射到最小所需权限。
- 新 Flyway 迁移创建主数据历史所需表结构、注册权限、将菜单作为“数据资产”子菜单初始化，并为默认管理员授予新模块权限；同步角色菜单关联初始化，避免升级后管理员菜单缺失。遵循当前 `classpath:db/mysql` Flyway 路径和迁移 SQL 约定。
- `PermissionCatalog` 的菜单组件映射和 `modulesForComponent` 包含 `assets/master-data`，确保导航只对获授权限的角色可见。
- 新增、编辑、删除、导入、导出和查看历史按结果写入 `audit_events`；失败也记录失败结果。`AuditCatalog` 为每个 action code 增加中文操作名，并为主数据记录对象类型增加中文名。审计消息仅记录对象标识、影响数量和错误摘要，不记录字段值、密码或完整导入行。
- 菜单、权限、审计操作名都使用稳定代码和版本迁移登记；代码注册表与数据库权限目录保持一致。

## 关键实现边界

- 通过现有加密数据源凭据、驱动配置和连接工厂访问外部数据库，不把密码传给前端；只访问 `data_objects` 中已登记的物理身份。
- 物理身份限定数据源、catalog/schema、表名和 TABLE/VIEW 类型。查询/写入 SQL 的字段名只能来自已登记且当前仍存在的字段，参数值使用 JDBC 参数绑定。
- 仅当对象可确认有主键时启用编辑和删除；导入每一行都按同样的数据表、字段与权限规则处理。视图始终只读。
- 数据集查询与已有对象预览 API 保持现有权限逻辑，不将主数据的独立授权扩展到查询、报表或其他模块。
- 页面遵守项目规范：查询条件在工具栏左侧、列表操作在右侧；目录面板与内容区同高，树区独立滚动；分页留在列表面板底部；窄屏时布局折叠且控件不溢出。

## 验收标准

1. 数据资产导航中可看到主数据菜单；菜单和权限初始化后，获授角色能进入，未获授角色看不到，且直接调用 API 同样被拒绝。
2. 左侧树覆盖不同对象目录下的全部已登记对象；搜索能定位对象；切换对象后字段、筛选和记录表格随之变化。
3. 有主键的数据表能查询、分页、新增、编辑和删除记录；复合主键定位正确；缺少主键对象不可编辑或删除；视图只读。
4. Excel 模板、导入和导出按当前对象字段工作；导入错误能定位到行；导出仅含筛选后的业务记录。
5. 主数据记录历史可查看新增/修改/删除/导入操作与修改差异，并严格受历史权限保护。
6. 主数据所有写入和数据转移操作的成功/失败均能在审计页显示正确的中文操作名和“主数据记录”对象类型；日志不包含记录的单元格内容。
7. 数据查询与对象预览原有数据集行/列策略行为不变。
8. 页面延续当前模块视觉风格并满足桌面和窄屏目录、工具栏、滚动及分页约定。

## 明确不纳入

- 改造数据查询、报表等模块的现有数据集授权机制。
- 对 VIEW 写入或对缺少主键的对象猜测行标识。
- 通用任意 SQL 执行、任意物理 schema 修改。
- 跨所有业务表强制增加状态/标签/审批字段或编码规则。
