# 数据处理 · 处理任务设计（一期～三期）

日期：2026-11-20
状态：已与用户逐节确认

## 背景与目标

平台现有任务引擎（`TaskStudio.vue`：SQL 加工 / 数据库同步任务、版本、工作流、定时计划、补跑、重试）功能完整，但旧菜单“任务与工作流”在 V24 迁移中删除后没有任何界面入口。本次新增一级菜单“数据处理”，把任务能力以参考项目 dip（`D:\sparta-project\sparta-dpp\monorepo\web\dip`，Vue2 + iView + AntV X6）的交互形态重新暴露，并逐步补齐画布编排与任务监控。

dip 的可借鉴交互：目录树组织任务、查询区点击“查询”生效、行内启动/停止/编辑/复制/删除、批量启停串行执行后汇总成功失败、两段式创建（基础信息弹窗→画布）、试运行日志+数据预览弹窗、独立监控页按实例展示日志/参数/处理概览。

## 关键决策（用户确认）

1. **复用并扩展现有任务引擎**：保留任务、版本、运行记录、`workflow.*` 权限体系；不新建平行任务模型。工作流/定时计划能力保留，入口暂不暴露。
2. **不要上线/下线状态**：只保留运行/停止状态（dip 的双状态模型裁剪为单状态）。
3. **一期～三期写入本规格**，四期（导入导出、任务级 cron 周期调度、单次运行、优先级）后续单独设计。
4. **排除**：集群管理、任务下发、告警中心——依赖多集群与通知体系，本平台为单节点架构。
5. 一期采用**新建独立页面 + 后端扩展**，不改造 TaskStudio。
6. 二期画布**扩展现有 @vue-flow/core**，不引入 AntV X6。
7. 二期预处理组件：字段映射、数据过滤、字段脱敏、字段计算。
8. 二期试运行**不写目标表**，限量安全预览。
9. 三期监控**同时纳入任务实例与工作流实例**。

### 页面结构与目录树

- 布局：左侧任务目录树（约 220px，`el-tree`）+ 右侧列表区。窄屏（≤700px）目录树折叠为顶部下拉选择，列表占满宽度。
- 树交互：
  - 虚拟根节点“全部任务”不可改删；点击根节点显示全部任务（含未分类）。
  - 目录节点悬停/右键操作：新增子目录、重命名、删除。目录名非空、≤120 字符；同一父级下允许重名（树以 id 区分）。
  - 非空目录（含任务或子目录）禁止删除，提示并返回 409。
  - 支持拖拽排序与跨父级移动（`el-tree` draggable），落点后批量提交排序；禁止移入自身子孙。
  - 点击目录节点按该目录**含子目录**过滤右侧列表。
- 任务的 `directory_id` 可空=未分类，仅在“全部任务”下可见；任务表单中目录选择可留空。

### 数据模型（V32）

```sql
CREATE TABLE task_directories (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    parent_id BIGINT NULL,
    name VARCHAR(120) NOT NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (parent_id) REFERENCES task_directories(id)
);
ALTER TABLE processing_tasks ADD COLUMN directory_id BIGINT NULL;
ALTER TABLE processing_tasks ADD CONSTRAINT fk_tasks_directory FOREIGN KEY (directory_id) REFERENCES task_directories(id);
ALTER TABLE processing_tasks ADD COLUMN description VARCHAR(500);
```

H2 版语法按现有迁移惯例调整（`GENERATED BY DEFAULT AS IDENTITY` 等）。

**运行状态不存字段**，由 `task_runs` 实时推导：任务存在 state 为 PENDING/RUNNING 的实例 → `runState='RUNNING'`，否则 `'STOPPED'`。`lastRun` 取该任务最新实例（max id）的 `{state, startedAt, finishedAt}`。

### API

目录（权限复用 `workflow.task.*`，全部登记路由守卫，增删改移记审计）：

| 端点 | 用途 | 权限 |
|---|---|---|
| `GET /api/task-directories` | 平铺列表 `{id, parentId, name, sortOrder}` | task.read |
| `POST /api/task-directories` | 新建 `{name, parentId?}` | task.create |
| `PUT /api/task-directories/{id}` | 重命名 `{name}` | task.update |
| `DELETE /api/task-directories/{id}` | 删除；含任务或子目录 409 | task.delete |
| `POST /api/task-directories/sort` | 拖拽后提交**全量**目录列表 `[{id, parentId, sortOrder}]`；校验 id 存在、禁止环；单事务替换 | task.update |

任务扩展：

| 端点 | 变化 |
|---|---|
| `GET /api/tasks` | 响应增加 `directoryId, description, runState, lastRun{state, startedAt, finishedAt}`；仍返回全量，前端客户端筛选分页（项目现有惯例） |
| `POST /api/tasks` | 请求增加 `directoryId?, description?` |
| `PUT /api/tasks/{id}`（新增） | 改基本信息 `{name?, directoryId?, description?}`，不产生新版本；运行中 409 |
| `DELETE /api/tasks/{id}`（新增） | 运行中 409；被工作流定义或工作流运行节点引用 409（沿用数据源保守删除惯例，扫描引用）；否则级联删除该任务自身的 runs/attempts/日志后删除版本与任务（任务删除即清除其运行历史，与 dip 一致），记审计 |
| `POST /api/tasks/{id}/runs` | 增加守卫：任务已有 PENDING/RUNNING 实例时 409，禁止重复启动 |
| `POST /api/tasks/{id}/stop`（新增） | 中断该任务全部 PENDING/RUNNING 实例；无运行中实例 409。权限复用 task.execute，记审计 |

**停止实现**：协作式取消。`TaskRunService` 维护按 runId 的取消标志；SYNC 执行器在批次间检查标志后关闭生产者/消费者；SQL 执行器注册 `Statement` 句柄，取消时调 `cancel()`；排队中（PENDING）实例直接置 INTERRUPTED。实例与 attempt 置 `INTERRUPTED`，错误信息“手动停止”。启动恢复逻辑（已有）不受影响。

**复制与批量启停不加后端接口**：复制=前端取最新版本配置预填新增弹窗（名称默认“原名-副本”）；批量=前端串行调单条接口后汇总。

### 列表交互（遵循 AGENTS.md 工具栏规范：左查询、右操作）

- 查询区：任务名称输入框（支持回车查询）、运行状态下拉（全部/运行中/停止）、“查询”按钮；当前目录名显示在查询区。
- 操作区：新增、批量启动、批量停止、刷新。
- 表格列：多选、序号、任务名称、类型（SQL 加工/数据库同步）、版本、目录、运行状态（标签）、最近运行（状态+时间）、操作。
- 行操作（文字按钮，交互语义对齐 dip）：
  - **启动/停止**：按 runState 切换。启动弹窗选业务日期（默认今天，显示将运行的版本号）→ 创建实例；停止 popconfirm 提示“停止会中断运行，可能已写入部分数据”。
  - **编辑/查看**：运行中为“查看”（只读弹窗）；停止时“编辑”打开任务表单。
  - **复制**：预填新增弹窗。
  - **删除**：popconfirm；运行中禁用。
  - **运行记录**：复用现有实例列表+执行记录+重试弹窗形态。
- 批量启动：勾选多行 → 一个业务日期弹窗 → 串行启动 → 汇总“启动成功：… / 启动失败：…”；批量停止在工具栏弹一次确认，确认后串行逐条执行（不再逐条确认），同样汇总成功/失败。
- 任务弹窗：现有表单字段（类型、源/目标数据源、SQL/同步配置、顺序参数、重试策略）+ 目录选择 + 描述。保存时基本信息走 `PUT /api/tasks/{id}`，配置变化走 `POST /api/tasks/{id}/versions`（保留版本语义）；新建走 `POST /api/tasks`。
- 状态刷新：页面存在 RUNNING 任务时每 5 秒轮询 `GET /api/tasks`，全部停止后自动停轮询；另有手动刷新按钮。

### 错误处理

- 409：运行中禁改/禁删/重复启动、目录非空、停止未运行任务 → 明确中文提示。
- 403：权限提示，与现有页面一致。
- 轮询失败不打断页面，仅提示一次；手动操作失败正常弹错。
- 窄屏工具栏换行：查询区在前、操作区靠右（Flex，无固定占位）。

## 二期：可视化画布编排

### 选型

扩展项目现有 `@vue-flow/core`（WorkflowCanvas.vue 与 flow-adapter.js 已在使用），零新依赖、风格统一。不引入 AntV X6：dip 为 Vue2 + X6 1.x，代码不可直接复用，引入 X6 2.x 仅增加重依赖与 Vue3 形状适配层。

### 任务模型

- 新增任务类型 `FLOW`（流程编排），与 SQL/SYNC 并列，存现有 `processing_tasks` / `processing_task_versions`，版本/权限/运行记录/停止体系完全复用。
- 配置 JSON：`{nodes:[{key, component, config, position:{x,y}}], edges:[{from,to}]}`。

### 节点组件（7 种）

| 分组 | component | 配置要点 |
|---|---|---|
| 来源 | SOURCE_TABLE | sourceId、schema、table |
| 来源 | SOURCE_SQL | sourceId、sql、顺序参数（沿用现有参数模型） |
| 预处理 | FIELD_MAP | mappings:[{from,to}]，改名/取舍上游字段 |
| 预处理 | FIELD_FILTER | 布尔表达式，保留为真的行 |
| 预处理 | FIELD_MASK | field；脱敏语义与数据集预览一致：字段值整体替换为 `****`（现实现见 DatasetQueryEngine，落地时抽为共享工具） |
| 预处理 | FIELD_CALC | field（新字段名）+ 表达式 |
| 目标 | SINK_TABLE | sourceId、schema、table、writeMode（APPEND/UPSERT）、keys（UPSERT 必填）、batchSize |

**表达式受限语法**（FIELD_FILTER / FIELD_CALC 共用）：字段引用、字符串/数字/布尔/空值字面量、算术 `+ - * /`、比较 `= != > < >= <=`、`AND OR NOT`、括号、函数 `UPPER LOWER TRIM SUBSTR CONCAT ABS ROUND`。自实现递归下降解析器 + 求值器，不执行任意代码；类型不匹配报明确错误。

**校验规则**：
- 保存时（结构）：无环；来源节点无入边、目标节点无出边；每个节点必填配置完整；至少一个来源和一个目标；节点 key 唯一。
- 运行时（字段）：按上游输出 schema 校验映射/过滤/计算/脱敏引用的字段存在；来源 schema 取自 JDBC 元数据或 SQL 预编译结果集元数据；错误信息指明节点与字段。

### 执行与试运行

- 新增 `FlowTaskExecutor`，实现与 SqlTaskExecutor/DatabaseSyncExecutor 相同的执行器接口：按拓扑序流式分批读→转换→写；正式运行创建 task_run 实例，写日志与节点统计（见三期存储节，二期落地）。
- 试运行 `POST /api/tasks/flow/test-run`，请求体 `{configuration}`（无需已保存任务），权限 task.execute：
  - 每来源限量 100 行；**不写目标表**，目标节点收集预览数据。
  - 同步返回 `{logs:[{lineNo,level,message}], previews:{nodeKey:{columns:[...], rows:[...]}}, stats:[...]}`。
  - 同步请求，30 秒超时；每来源读取 ≤100 行，每个目标节点预览返回 ≤100 行。

### 画布 UI（dip 同款三栏）

- 左侧组件面板：来源/预处理/目标三分组，拖拽或点击入画布。
- 中间 VueFlow 画布：自定义节点卡片（图标+名称+组件类型+配置摘要）；连线遵守层级规则，非法连接即时提示。
- 右侧节点配置抽屉（Element 风格）：点击节点打开，按组件类型动态表单，底部取消/确定。
- 头部按钮：试运行、保存、返回。
- 创建流程对齐 dip 两段式：列表“新增”→ 基础信息弹窗（名称/目录/描述/类型=流程编排）→ 进入画布编辑态（ProcessingTasks 页内视图切换，沿用 TaskStudio 详情态模式）；画布“保存”→ 创建任务/新版本 → 回列表。编辑 FLOW 任务直接进画布。
- 试运行弹窗双 Tab：运行日志 / 数据预览（每个目标节点一个子 Tab，表格展示）。

### API 增量

- `POST /api/tasks/flow/test-run`（新增，task.execute，路由守卫）。
- `POST /api/tasks` / `POST /api/tasks/{id}/versions`：TaskDefinitionValidator 扩展 FLOW 结构校验。
- 其余复用一期端点（FLOW 任务的启动/停止/删除/运行记录同 SQL/SYNC）。

## 三期：任务监控

### 日志与统计存储（V33，二期随执行器落地）

```sql
CREATE TABLE execution_logs (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    owner_type VARCHAR(20) NOT NULL,      -- TASK_RUN | WORKFLOW_NODE
    owner_id BIGINT NOT NULL,
    attempt_no INTEGER NOT NULL,
    line_no INTEGER NOT NULL,
    level VARCHAR(10) NOT NULL,           -- INFO | WARN | ERROR
    message VARCHAR(2000) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_execution_logs_owner ON execution_logs(owner_type, owner_id, attempt_no, line_no);
ALTER TABLE task_run_attempts ADD COLUMN stats TEXT;
ALTER TABLE workflow_node_attempts ADD COLUMN stats TEXT;
```

- 每实例每次 attempt 日志上限 2000 行，超出截断并追加一条 WARN 标记。
- `stats` JSON：FLOW 按节点 `[{nodeKey, rowsIn, rowsOut, durationMs}]`；SQL/SYNC 单节点读写行数。
- 执行器接收统一 LogSink 接口：TaskRunService 提供 TASK_RUN sink，WorkflowWorker 提供 WORKFLOW_NODE sink——任务与工作流共用日志管道。
- 日志内容：启动/节点切换/批次进度（每 N 批一条）/错误/完成计数；不记录数据行内容。

### 菜单与权限（V34）

- 二级菜单“任务监控”：`id=32`、`parent_id=3`、类型 M、`route_path='/processing/monitor'`、`component='processing/monitor'`、`icon='pulse'`（复用）、`sort_order=20`。
- `modulesForComponent` 增加 `case "processing/monitor" -> Set.of("workflow.task", "workflow.workflow")`：任一权限可见菜单。
- 实例可见性按类型过滤：任务实例需 `workflow.task.read`，工作流实例需 `workflow.workflow.read`。
- 前端新增 `TaskMonitor.vue`，由 `section === 'processing'` 分支按 view 渲染。

### 监控页

- 查询区：实例类型下拉（任务/工作流）、名称输入（回车）、运行状态下拉 + 查询按钮；操作区仅刷新（监控只读，不记审计）。
- 列表列：实例编号、类型、名称、版本、业务日期、状态、开始时间、结束时间、耗时、操作（详情）。
- **服务端游标分页**（beforeId + limit ≤ 100，沿用工作流历史接口模式），不做全量加载。
- 详情弹窗：
  - 上部只读基本信息：名称/编号、版本、业务日期、状态、创建/开始/结束时间、耗时、错误信息；工作流实例附节点状态表（节点标识、状态、执行记录）。
  - 下部三 Tab：
    - **运行日志**：默认最新 attempt，可用下拉切换历史 attempt；运行中每 2 秒按 `afterLine` 增量拉取（dip 同款），级别标签 + 自动滚动；结束即停轮询。
    - **运行参数**：任务配置 JSON / SQL 文本、工作流图摘要，代码块展示。
    - **处理概览**：节点级 rowsIn/rowsOut 表格 + echarts 柱状图（现有依赖）。

### API

| 端点 | 用途 | 权限 |
|---|---|---|
| `GET /api/monitor/instances?kind=&state=&name=&beforeId=&limit=` | 统一实例列表（只返回有权类型） | task.read / workflow.read |
| `GET /api/monitor/instances/{kind}/{id}` | 详情：基本信息 + 节点状态 + stats + 配置 | 同上按类型 |
| `GET /api/monitor/instances/{kind}/{id}/logs?attempt=&afterLine=` | 增量日志 | 同上按类型 |

kind 取值 `task` | `workflow`；全部登记路由守卫。
